# SwitchLoc v1.9.7 — یادداشت انتشار

## گردش‌کار بازبینی مکان و زون رخداد خاموشی

1. پس از ورود فایل خاموشی و اجرای توپولوژی، دکمه **Review outage places / zones** در تب Data Import فعال می‌شود.
2. جدول بازبینی، شماره رخداد، فیدر، تاریخ، شرح حادثه، نام مکان پیشنهادی و فهرست زون‌های شبکه را نمایش می‌دهد.
3. موتور جست‌وجوی آفلاین نام آبادی را از شرح/توضیحات پیشنهاد می‌کند. این پیشنهاد به‌هیچ‌وجه انتساب خودکار نیست؛ در صورت خالی بودن بانک جغرافیایی، ستون مکان پیشنهادی خالی می‌ماند.
4. مهندس مکان را از فهرست پیشنهادی (در صورت وجود) و زون متاثر را مستقل انتخاب می‌کند و وضعیت را «تأیید مهندس» یا «رد رخداد» قرار می‌دهد. ردیف‌های pending یا فاقد زون ذخیره نمی‌شوند.
5. تصمیم‌ها در جدول `outage_event_review` پایگاه داده پروژه ذخیره می‌شوند و هنگام بازکردن مجدد پنجره بازبینی، قابل مشاهده/ویرایش‌اند.

## محاسبه U×P زون

برای رخدادهای تأییدشده:

- `U_zone,total = Σ duration_event / 60`
- `U_zone,annual = U_zone,total / exposure_years`
- `UP_zone = P_zone(kW) × U_zone,annual(h/year) / 1000`

بار زون از همان `zone_load_map` و مدل بار جاری مطالعه (یا تخصیص N-1 پس از جایابی) خوانده می‌شود. زمان مواجهه از پوشش واقعی داده در تحلیل خاموشی گرفته می‌شود. اگر پوشش معتبر یا بار مثبت و قابل محاسبه موجود نباشد، U×P محاسبه نمی‌شود و لیبل نقشه «نامشخص» باقی می‌ماند.

**محدودیت تفسیر:** مدت رخداد ثبت‌شده در اکسل لزوماً زمان خاموشی همه مشترکان زون نیست. برای تبدیل مدت کل رخداد به مدت خاموشی واقعی هر زون، مهندس باید زون متاثر و مدت مؤثر قطع آن را بر اساس گزارش مانور/ایزولاسیون تأیید کند. نسخه فعلی برای هر رخداد یک زون و مدت ثبت‌شده همان رخداد را می‌پذیرد؛ رخداد چندزون یا مدت‌های متفاوت زون‌ها باید به‌صورت رکوردهای تفکیک‌شده در منبع وارد شوند. این محدودیت عمداً پنهان نشده است.

## وضعیت داده جغرافیایی استان اردبیل

بانک `data/geography/ardabil_places.sqlite` هنوز خالی است؛ بنابراین قابلیت پیشنهاد نام آبادی تا زمان ورود GeoJSON/CSV مرجع فعال داده‌ای نخواهد داشت. منبع قابل استفاده برای تکمیل اولیه، استخراج روزانه OSM ایران از Geofabrik است؛ استخراج ایران حدود ۲۱۹ مگابایت PBF یا ۴۲۶ مگابایت Shapefile دارد و زیرمنطقه مستقل برای ایران ارائه نمی‌کند، پس لازم است ابتدا مرز استان معتبر اخذ و نقاط آبادی با آن برش داده شوند. داده OSM تحت ODbL است و باید انتساب منبع حفظ شود. برای استفاده عملیاتی، لایه رسمی آبادی‌ها و مرزهای مورد تأیید شرکت/سازمان نقشه‌برداری اولویت دارد. منبع: https://download.geofabrik.de/asia/iran.html
