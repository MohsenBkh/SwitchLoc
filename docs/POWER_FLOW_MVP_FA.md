# پخش بار شعاعی متعادل — نسخهٔ اول

این قابلیت یک پخش بار سه‌فاز متعادل/توالی مثبت برای یک فیدر شعاعی اجرا می‌کند. الگوریتم Backward/Forward Sweep است؛ بارها به‌صورت P/Q ثابت، امپدانس خط به‌صورت R/X سری و منبع به‌صورت باس مرجع در نظر گرفته می‌شوند.

## تفاوت با EENS فعلی

- روش EENS موجود برای خرابی‌ها نرخ λ را روی طول قطعات پخش می‌کند و بارِ قطع‌شده و زمان تعمیر/بازیابی را برای محاسبهٔ EENS برآورد می‌کند. مدل فعلی ولتاژ شینه، جریان هر خط، افت ولتاژ یا بارگیری واقعی ترانس را حل نمی‌کند.
- روش سطح دوم PDF ارسالی، ENS/EENS را هدف نگه می‌دارد، ولی برای هر حالت کلیدزنی، قیود بهره‌برداری پخش بار را هم لازم دارد: حدود جریان خطوط، ظرفیت ترانس، بازهٔ ولتاژ و شعاعی‌بودن توپولوژی. بنابراین دو روش مترادف نیستند؛ پخش بار لایهٔ فیزیکی/قیود تازه‌ای اضافه می‌کند و می‌تواند یک حالت جایابی را نامعتبر کند.
- نسخهٔ حاضر **حل حالت عادی هر فیدر و گزارش قیود آن** را اضافه می‌کند؛ هنوز پخش بار را برای تک‌تک طرح‌های جایابی و سناریوهای بازیابی/انتقال بار در جست‌وجوی EENS اجرا نمی‌کند. برای اتصال درست آن مرحله، توپولوژی کلیدزنی پس از خطا، کلیدهای NO و مسیر/ظرفیت انتقال پشتیبان باید مدل شوند؛ اعمال نتیجهٔ حالت عادی به‌جای قیود هر سناریو گمراه‌کننده خواهد بود.

## دادهٔ لازم

دادهٔ GIS کنونی به‌تنهایی کافی نیست: نام/سطح هادی و طول خط، امپدانس اهمی R/X را تعیین نمی‌کنند. باید موارد زیر با دادهٔ تأییدشدهٔ شرکت وارد شوند:

1. ولتاژ خط‌به‌خط منبع (kV) و ولتاژ pu منبع؛
2. R و X ممکن است از تطبیق یکتای workbook خوانده شود؛ حد جریان (A) باید تأییدشده باشد و در `type_ampacity_a` بر اساس نام تایپ ثبت شود، یا R/X/جریان از `line_catalog` / `edge_overrides` صریح داده شود؛
3. حد ولتاژ و حد بارگیری ترانس؛ ظرفیت ترانس‌های GIS برای حد بارگیری استفاده می‌شود؛
4. بار P و Q. در مدل بار `scaled`، Q ورودی فیدر به نسبت ظرفیت ترانس‌ها پخش می‌شود. در مدل‌های بدون Q واقعی، ضریب توان فرضی در تنظیمات باید تأیید شود.

**تایپ خط فقط با قواعد محافظه‌کارانه از فیلدهای GIS انتخاب می‌شود** و نتیجهٔ انتخاب/ابهام همراه شناسه، فیدر و مقادیر GIS در خروجی JSON ثبت می‌شود. فایل همراه پروژه `data/catalog/types_override.xlsx` است. برای این نسخه، کابل زمینی با جنس/سطح مقطع دقیق، ACSR هوایی لخت ۳۵/۷۰ و نام هادی Hyena قابلیت تطبیق مشخص دارند؛ موارد دیگر بدون انتخاب خودکار باقی می‌مانند. ظرفیت ترانس و جریان/ولتاژ فیوز هم در کاتالوگ بررسی می‌شوند، اما چند تایپ ترانس با ظرفیت برابر مبهم می‌مانند و برای بریکر/سکسیونر workbook تایپی ندارد.

R/X خط از ردیف تایپ یکتای workbook قابل استفاده است، ولی جریان‌پذیری به‌صورت حدس از ستون‌های جریان workbook گرفته نمی‌شود. برای استفاده از R/X تایپ در حل پخش بار، حد جریان تأییدشدهٔ مهندس را با نام تایپ در `type_ampacity_a` وارد کنید؛ در غیر این صورت می‌توان از `line_catalog` یا `edge_overrides` صریح فعلی استفاده کرد. خطوط بی‌مشخصات همچنان مانع حل می‌شوند.

## اجرای CLI

یک فایل JSON بسازید و مقادیر آن را با کاتالوگ واقعی جایگزین کنید:

```json
{
  "base_voltage_kv": 20.0,
  "source_voltage_pu": 1.0,
  "voltage_min_pu": 0.95,
  "voltage_max_pu": 1.05,
  "transformer_loading_limit_pct": 100.0,
  "assumed_power_factor": 0.95,
  "line_catalog": {
    "نام دقیق هادی|50|OVERHEAD": {
      "r_ohm_per_km": 0.30,
      "x_ohm_per_km": 0.35,
      "max_current_a": 210.0
    }
  },
  "edge_overrides": {}
}
```

اعداد بالا صرفاً برای نمایش قالب JSON هستند و **دادهٔ معتبر هیچ فیدری نیستند**. مقدار کلید کاتالوگ به‌شکل `CONDUCTOR|SECTION_MM2|INSTALLATION` ساخته می‌شود؛ برای سطح یا نصب از wildcard `*` می‌توان استفاده کرد، ولی نام هادی باید دقیقاً منطبق باشد. `edge_overrides` می‌تواند `edge_id` یا شناسهٔ `branch_id` را کلید بگیرد و همان سه پارامتر R/X/حد جریان را داشته باشد. برای تطبیق workbook، `type_ampacity_a` نگاشت نام دقیق تایپ به آمپرِ تأییدشده است؛ نمونهٔ قالب (عدد ظرفیت جریان باید از منبع معتبر مهندسی بیاید، نه از این مثال):

```json
"type_ampacity_a": {
  "35-Al_St": 170.0,
  "N2XSY 1x70/16 (12/20kV)": 210.0
}
```

`--types-catalog` مسیر workbook جایگزین را می‌پذیرد؛ اگر حذف شود، نسخهٔ همراه پروژه استفاده می‌شود. در گزارش JSON، `equipment_types.feeders` تطبیق‌ها و کاندیدهای حل‌نشده را به تفکیک فیدر نگه می‌دارد.

```bash
python -m switchloc loadflow projects/PROJECT.sqlite \
  --config power_flow.json \
  --feeders "F6 - SOLOUT" \
  --out-dir reports/loadflow
```

حذف `--feeders` همهٔ فیدرهای ردیابی‌شده را اجرا می‌کند. تنظیم مدل بار از `project_kv.engineering_load_model_v1` خوانده می‌شود. گزارش Markdown و JSON شامل ولتاژ حداقل/حداکثر، بیشینهٔ بارگیری خط و ترانس، تلفات، source P/Q، همگرایی و نقض قیود است. اجرای CLI پروژه را تغییر یا ذخیره نمی‌کند.

## مرزهای اعتبار

- این نسخه فقط شبکهٔ شعاعی، متعادل، بدون تولید پراکنده، بدون شنت، بدون مدل امپدانس ترانس و بدون کنترل تپ را حل می‌کند؛ حلقه/یال اضافی رد می‌شود و به‌جای درخت پوشا، نتیجهٔ تقریبی ارائه نمی‌شود.
- قیود جریان فقط وقتی ارزیابی می‌شوند که برای همهٔ خطوط R/X و آمپاسیتی فراهم باشد. ظرفیت ترانس ناموجود برای گرهٔ باردار، قید را «ناقص» و فیدر را غیرقابل تأیید می‌کند.
- وضعیت‌های چندگانهٔ پس از خطا، مانور NO، تبادل بین فیدرها، انتقال بار و EENS هر حالت هنوز بخشی از این MVP نیستند. خروجی پخش بار را به‌تنهایی نباید تأیید مهندسی طرح جایابی تلقی کرد.
