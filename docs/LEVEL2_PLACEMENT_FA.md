# جایابی سطح دوم با قید پخش بار

این نسخه فرمان `optimize-level2` را برای جست‌وجوی شمارشیِ آرایش‌های NC/NO اضافه می‌کند. تابع هدف، کمینه‌کردن EENS سالانهٔ موتور قابلیت اطمینان پروژه است؛ قیود پخش بار حالت ماندگار و شعاعی‌بودن به‌صورت **قید سخت** اعمال می‌شوند. هر آرایش نامجاز رد می‌شود؛ به آن جریمهٔ عددی داده نمی‌شود.

## جست‌وجو

- همهٔ فیدرهای ردیابی‌شده در پروژه بررسی می‌شوند.
- برای هر فیدر تعداد دقیق نصب NC در `nc_budget_by_feeder` تعیین می‌شود؛ فیدری که در آن نگاشت نیامده بود بودجهٔ صفر دارد و همچنان در محاسبات/گزارش می‌ماند.
- `no_budget` تعداد نقاط اتصال موجودی است که به‌عنوان نامزد NO بررسی می‌شوند. نقطه‌ها از کاندیدهای اتصال توپولوژی گرفته می‌شوند؛ شناسه و منشأ هر نقطه در خروجی می‌آید. این‌ها پیشنهادند، نه تأیید وضعیت کلید.
- جست‌وجو برای هر سه نوع `recloser`، `sectionalizer` و `disconnector` جداگانه انجام می‌شود. اگر آرایش مشترک باشد، EENS آن‌ها ممکن است به‌علت مدل خطای گذرا/زمان بازیابی متفاوت باشد.
- کاندیدهای NC به‌طور پیش‌فرض به گره‌های دارای بار صریح محدودند (`candidate_mode: load_points`). `all_nodes` فضای جست‌وجو را بسیار بزرگ می‌کند.
- هیچ کوتاه‌سازی پنهان وجود ندارد. اگر شمار حالت‌های دقیق از `max_search_states` بیشتر شود، فرمان با خطای روشن متوقف می‌شود.

## ورودی‌های الزامی و منشأ

در رابط Qt دیگر بارگذاری فایل JSON لازم نیست: تب سطح ۲ فقط فیدرهای انتخاب‌شده در دامنهٔ مطالعهٔ عمومی نرم‌افزار را بررسی می‌کند. دکمه‌های «برداشت P/Q از تنظیمات بار» و «تکمیل λ/r و پشتیبان از ورودی‌های پروژه» جدول‌ها را از مدل بار، سوابق خاموشی/اصلاحات λ/r و تنظیمات ظرفیت پشتیبان پر می‌کنند؛ در نبود نرخ/زمان تعمیر فیدر، fallback عمومی از تنظیمات جایابی اعمال و در فرم اعلام می‌شود. بودجهٔ کلید و قیود پخش بار نیز مستقیم در فرم وارد می‌شوند. تنظیمات اجرا در همان پروژه ذخیره می‌شود. R/X و `Sline(r)` از `types_override.xlsx` خوانده می‌شوند؛ Sline بر حسب kA است و به آمپر تبدیل می‌شود. مقدار تبدیل‌شده در فرم قابل بازبینی/اصلاح است. `Ithr(r)` حد جریان اتصال کوتاه است و در پخش بار استفاده نمی‌شود.

فرمان CLI همچنان فایل JSON می‌پذیرد. نمونهٔ ساختار (اعداد پارامترهای الکتریکی در این قالب نمونه‌اند و نباید به‌عنوان مقادیر شبکه استفاده شوند):

```json
{
  "level2": {
    "nc_budget_by_feeder": {
      "F1 - FEEDER NAME": 1,
      "F2 - FEEDER NAME": 1
    },
    "no_budget": 1,
    "max_search_states": 100000,
    "candidate_mode": "load_points",
    "switch_types": ["recloser", "sectionalizer", "disconnector"]
  },
  "load_model": {},
  "power_flow": {
    "base_voltage_kv": 20.0,
    "source_voltage_pu": 1.0,
    "voltage_min_pu": 0.95,
    "voltage_max_pu": 1.05,
    "transformer_loading_limit_pct": 100.0,
    "assumed_power_factor": 0.95,
    "line_catalog": {},
    "edge_overrides": {},
    "type_ampacity_a": {}
  },
  "reliability": {
    "failure_rates": {},
    "repair_times_min": {},
    "default_failure_rate_per_year": null,
    "default_repair_time_min": null,
    "transient_rates": {},
    "backup_kw": {},
    "engine": {
      "restoration_model": "directional",
      "repair_time_min": 50,
      "restoration_time_min": 30
    }
  },
  "equipment_types_catalog": "data/catalog/types_override.xlsx",
  "persist": false
}
```

- مدل بار از `load_model` همین تنظیم یا `engineering_load_model_v1` پروژه خوانده می‌شود. مدل بار باید برای شبکه بار اکتیو بدهد؛ اگر Q صریح نباشد، ضریب توان تنظیم‌شده فرض می‌شود و در گزارش ثبت می‌گردد.
- نرخ خرابی و زمان تعمیر از دادهٔ خاموشی پروژه خوانده می‌شوند؛ ورودی‌های صریح `failure_rates` و `repair_times_min` بر آن‌ها اولویت دارند. برای فیدری که داده ندارد باید مقادیر واقعی یا default صریح فراهم شود؛ مقدار پیش‌فرض پنهان وارد نمی‌شود.
- `line_catalog` / `edge_overrides` یا تطبیق تایپ workbook به‌همراه آمپاسیتی تأییدشده در `type_ampacity_a` باید مشخصات هر یال را پوشش دهند. از ستون‌های با واحد تأییدنشدهٔ workbook برای آمپاسیتی استفاده نمی‌شود. دادهٔ ناقص یعنی آرایش از نظر پخش بار قابل تأیید نیست.
- ظرفیت ترانس GIS برای قید بارگیری استفاده می‌شود؛ ظرفیت/حد بارگیری ناموجود قید را ناقص می‌کند.

## اجرا

```bash
python -m switchloc optimize-level2 projects/PROJECT.sqlite \
  --config level2.json \
  --out-dir reports/level2
```

گزارش Markdown و JSON شامل EENS پایه و پس از طرح برای هر نوع کلید، تفکیک فیدرها، محل NC/NO، تعداد حالت‌های جست‌وجو و وضعیت پخش بار فیدرها است. `persist: true` نتیجه را در `project_kv.level2_placement_study` ذخیره می‌کند؛ پیش‌فرض خاموش است.

## مرز اعتبار

- NCهای جدید در حالت عادی بسته‌اند؛ نصب آن‌ها به‌تنهایی پخش بار عادی را تغییر نمی‌دهد. برای هر آرایش NO، توپولوژی با وضعیت انتخابی دوباره ردیابی و پخش بار همهٔ فیدرها از نو حل می‌شود.
- تابع هدف از مدل قابلیت اطمینان موجود و تنظیم بازیابی آن استفاده می‌کند. توالی مانور پس از تک‌تک خرابی‌ها از GIS استنتاج نمی‌شود؛ قاعدهٔ بازیابی، نرخ‌ها، ظرفیت پشتیبان و زمان‌ها باید با رویهٔ بهره‌برداری شرکت سازگار باشند.
- نقاط NO توپولوژی ابتدا کاندید هستند؛ طرح نهایی قبل از بهره‌برداری نیازمند تأیید مهندس/دیسپاچینگ است.
- حل پخش بار فعلی سه‌فاز متعادل، حالت ماندگار، بار P/Q ثابت و شبکهٔ شعاعی است. تولید پراکنده، نامتعادلی فاز، شنت، دینامیک کلید و پخش بار گذرا در این نسخه مدل نمی‌شوند.
- انتخاب هدف فقط EENS است (همان فرض نمونهٔ روش سطح ۲ با بودجهٔ ثابت). اگر هزینهٔ متفاوت تجهیزات/عملیات در تابع هدف لازم باشد، باید ضرایب هزینهٔ تأییدشده نیز وارد شوند.
