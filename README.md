## تنظیمات پیشرفته و عملیات

- **CRS**: از لایه‌های ایمپورت‌شده خوانده می‌شود؛ هیچ پیش‌فرض ثابتی (مثلاً UTM 39N) فرض نمی‌شود. اگر پروژه CRS نداشته باشد پس‌زمینهٔ OSM غیرفعال و پیام روشن نشان داده می‌شود.
- **لیست خاموشی با سرستون متفاوت**: تطبیق سرستون‌ها نسبت به ی/ک عربی، نیم‌فاصله و فاصله‌های اضافه مقاوم است. برای عبارات دیگر فایل `outage_columns.json` (یا مسیر `SWITCHLOC_OUTAGE_COLUMNS`) بسازید: `{"نام خط": "feeder_raw", "تاریخ": "date_raw"}`. فیلدهای مجاز: `event_no, substation, feeder_raw, date_raw, time_raw, duration_raw, restore_raw, cause_raw, device_raw, energy_raw, trip_current_raw, notes_raw`. سرستون‌های ناشناخته و ستون‌های ضروری گم‌شده در پنل نتیجه هشدار داده می‌شوند.
- **مسیر کار**: `SWITCHLOC_HOME` (پیش‌فرض: پوشهٔ جاری؛ اگر قابل‌نوشتن نبود `~/Documents/SwitchLoc`) شامل `projects/` و `reports/`.
- **نسخه‌بندی پروژه**: `PRAGMA user_version`؛ پروژهٔ ساخته‌شده با نسخهٔ جدیدتر باز نمی‌شود، ارتقای پروژهٔ قدیمی با پشتیبان `*.pre-migration-vN.sqlite` انجام می‌شود.
- **تست رابط**: `QT_QPA_PLATFORM=offscreen python -m pytest tests -q` (تست‌های Qt در نبود PySide6 رد می‌شوند و در CI اجباری‌اند).

## اجرا

```bash
pip install -r requirements.txt                    # هستهٔ محاسباتی (همه وابستگی‌های واقعاً import‌شده)
pip install -r requirements-qt.txt                 # پوسته گرافیکی
pip install -r requirements-report.txt             # (اختیاری) PDF بومی؛ نبودش: Word را به PDF چاپ کنید
pip install -r requirements-gpkg.txt               # (اختیاری، سنگین) ورودی GeoPackage
pip install -r requirements-dev.txt                # توسعه: pytest, pyinstaller, ruff

# فاز ۱ — ورود داده (مسیر پیش‌فرض: خلخال در sandbox؛ قابل تغییر با متغیر محیطی):
SWITCHLOC_SAMPLE_DIR="مسیر پوشه خروجی GIS" python scripts/import_sample.py
# فاز ۲ — توپولوژی روی پروژه فاز ۱ (گزارش + نقشه‌ها):
python scripts/build_topology.py
# یا مستقیم با CLI:
python -m switchloc topology projects/<project>.sqlite --report-dir reports

# فاز ۳ — تحلیل خاموشی‌ها (طبقه‌بندی + ماتریس λ/r):
python scripts/analyze_outages.py
# یا مستقیم با CLI:
python -m switchloc outages data/outages_1405.xlsx --out-db projects/<project>.sqlite --report-dir reports

# فاز ۴ — رتبه‌بندی فیدرها و جایابی کلید (گام‌های ۴-۸ روش سطح اول):
python -m switchloc placement projects/<project>.sqlite \
    --outages data/outages_1405.xlsx --report-dir reports
# ظرفیت نامی فیدرها (اختیاری — شرط ۲/۳ رابطه ۱۱ و سقف انتقال را فعال می‌کند):
python -m switchloc placement projects/<project>.sqlite --rated "F1=20000,F2=15000"

# بانک آفلاین مکان‌های اردبیل — جست‌وجو/آمار (بدون شبکه):
python -m switchloc places "زرج آباد" "سكر اباد" --limit 2
python -m switchloc places --stats

# روش جایابی بهینهٔ کلید و کاهش EENS (روش کد مرجع PowerFactory؛ نام قدیمی: sectionalizer):
python -m switchloc switches projects/<project>.sqlite --switch-type sectionalizer --no-persist \
    --max 3 --model uniform --lambda-source outage --report-dir reports
# λ صریح بعضی فیدرها و محدودکردن به چند فیدر:
python -m switchloc switches projects/<project>.sqlite \
    --lambda-override "F3=27,F5=57.3" --feeders F3,F5

# فاز ۵ — خروجی‌های تحویل‌شدنی (اکسل + ورد + PDF + GIS) از یک اجرای واحد:
```

## اجرای سریع در ویندوز — حالت EXE / dist (تک‌فایل، بدون venv)

| فایل | کار |
|---|---|
| `RUN.bat` | اجرای یک‌کلیکی فقط با فایل اجرایی — بدون Python، بدون pip و بدون محیط مجازی؛ `dist\SwitchLoc.exe` (دسکتاپ) یا `dist\SwitchLocCLI.exe` (خط فرمان) را اجرا می‌کند. اگر exe هنوز ساخته نشده باشد، پیام می‌دهد که یک‌بار `BUILD.bat` را اجرا کنید |
| `BUILD.bat` | ساخت یک‌کلیکی — بررسی Python 3.10+، نصب مستقیم وابستگی‌ها (شامل ابزارهای اختیاری گزارش `requirements-report.txt`)، تست دود ایمپورت، آزمون‌های مهندسی (با `SKIP_TESTS=1` قابل رد)، ساخت دو exe «تک‌فایلی» با PyInstaller (فونت‌ها و ابزارهای PDF باندل می‌شوند) و کپی `projects\` + `data\` + `README.md` کنار exe تا `dist\` کامل و قابل‌ارسال باشد |

```bat
BUILD.bat                                     :: یک‌بار: تست‌ها + ساخت دو exe تک‌فایلی در dist\
RUN.bat                                       :: پوسته دسکتاپ (dist\SwitchLoc.exe)
RUN.bat projects\<project>.sqlite       :: پوسته دسکتاپ روی یک پروژه (پروژه هنگام بالا آمدن باز می‌شود)
RUN.bat cli topology projects\<project>.sqlite --report-dir reports
RUN.bat cli report projects\<project>.sqlite   :: اکسل + ورد + PDF + GIS در reports\exports\
set SKIP_TESTS=1 && BUILD.bat                 :: ساخت بدون اجرای آزمون‌ها
```

- **یک فایل اجرایی تجمیع‌شده، بدون `_internal`**: هر دو exe با `--onefile` ساخته می‌شوند؛ در `dist\` فقط `SwitchLoc.exe` و `SwitchLocCLI.exe` هستند (به‌همراه پوشه‌های `projects\\` و `data\\`).
- **اسپلش و لوگو**: از نخستین لحظه اجرا اسپلش SwitchLoc بالا می‌آید و مراحل «Loading engineering modules… → Opening project… → Ready» را نشان می‌دهد و پس از آماده‌شدن پنجره بسته می‌شود. اجرای اول چند ثانیه بیشتر طول می‌کشد (استخراج exe تک‌فایلی) که همان اسپلش پوشش می‌دهد.
- **بدون پنجره cmd**: رابط دسکتاپ با `--windowed` ساخته می‌شود؛ خطاهای غیرمنتظره در لاگ چرخشی `%LOCALAPPDATA%\SwitchLoc\logs\switchloc.log` (لینوکس: `~/.local/state/switchloc/`؛ قابل تغییر با `SWITCHLOC_LOG_DIR`) ثبت و همزمان در یک پیام‌باکس نمایش داده می‌شوند؛ منوی Help ← Open log folder. هیچ خرابی بی‌صدا نیست.
- **زبان رابط**: پیش‌فرض انگلیسی؛ از View ← Language می‌توان «فارسی» (چیدمان RTL) را انتخاب کرد (در اجرای بعدی اعمال می‌شود). منوها، نوار ابزار، ناوبری، نوار وضعیت، دکمه‌های اصلی و مراحل گردش کار دو‌زبانه‌اند؛ پنل‌های مهندسی طولانی همان متن دو‌زبانهٔ قبلی را دارند (خروجی‌های Word/PDF/Excel فارسی‌اند).
- تنها پیش‌نیاز `BUILD.bat` پایتون ۳.۱۰+ روی PATH است (۳.۱۱ یا ۳.۱۲ توصیه می‌شود)؛ وابستگی‌ها مستقیماً در پایتون نصب‌شده روی سیستم نصب می‌شوند (بدون venv)؛ خروجی در پوشهٔ `dist\\` است؛ `WITH_GPKG=1` پشتیبانی GeoPackage را هم اضافه می‌کند. اسپلش به Tcl/Tk همراه پایتون ویندوز نیاز دارد — `--exclude-module tkinter` را در گام `[5/6]` حذف نکنید. برای بازگشت کنسول دیباگ، `--windowed` را از همان گام بردارید. برای توزیع روی سیستم‌های دیگر کافی است پوشه `dist\` را کپی کنید.

**پک زوم تب Map** (بدون وابستگی جدید):

- **اسکرول موس** = زوم روی نقطه نشانگر (هر پله ×۱٫۲۵؛ عمق زوم داخل تا **۱۰٬۰۰۰×** — ۱۰ برابر بیشتر به درخواست کاربر؛ برای دیدن انشعابات تک‌مشترک و ترانس‌های تکی — و بیرون تا ۸×؛ پله نهایی دقیقاً روی سقف می‌نشیند)
- **کشیدن با کلیک چپ** = پن نقشه (دست بسته)؛ **دابل‌کلیک** = زوم به داخل
- دکمه‌های **Zoom in / Zoom out / Fit view** + نشانگر زنده با **اسکیل ۰–۱۰۰٪** (بازخورد کاربر: ۰٪ = نمای کامل، ۱۰۰٪ = عمیق‌ترین زوم؛ ضریب مطلق هم به شکل «×N» کنارش نمایش داده می‌شود)
- **Feeder:** فیلتر نمایش یک فیدر (All feeders / F1..Fn) و چک‌باکس **Zone labels** برای برچسب زون‌ها
- **نقشه full-frame (بازخورد کاربر):** چرخش ۹۰° حذف شد — منظور از landscape استفاده از «تمام فضای» قاب بود: بوم با aspect خودکار کل فضای ویجت را پر می‌کند (بدون فضای خالی کنار نقشه) و یک **border** محدوده قابل نمایش را مشخص می‌سازد
- **لجند کامل:** همه نمادهای داخل نقشه — رنگ هر فیدر، خط ردیابی‌نشده، نقطه ترانس، دایره کلید بسته، لوزی نقطه باز/NO، مربع پست منبع و ستاره کلید پیشنهادی

**تفکیک فیدرها (TOPO-POL-05 — فیکس مهم):** در داده نمونه هیچ کلیدی وضعیت NO/NC ندارد (A-09)؛ در نتیجه با سیاست قبلی، BFS هر فیدر از کلیدهای با وضعیت نامشخص عبور می‌کرد و فیدرهای F2 تا F7 یک ردیابی یکسان و غرق‌شده در هم می‌گرفتند (نقشه همه فیدرها شبیه هم بود). اکنون ردیابی با «دروازه برچسب فیدر» انجام می‌شود: قطعه‌ای که GIS آن را به فیدر دیگری منسوب کرده عبور نمی‌کند — برچسب فیدرِ GIS همان تفکیک واقعی وضعیت عادی است. نتیجه روی داده خلخال: F1=1,196 / F2=343 / F3=614 / F4=5,721 / F5=3,019 / F6=12 / F7=564 یال با صفر هم‌پوشانی؛ قطعات قابل‌دسترس‌نشدنی در `TOPO-UNTRACED-AREA` شمارش و ثبت می‌شوند و فیدر محصورشده به مسیر بدون دروازه برمی‌گردد (هشدار صریح، هرگز خاموش نیست).

نکته محتوا: نقشه هر چیزی را نشان می‌دهد که وارد شده است. داده نمونه همراه پروژه، شبکه واقعی **فیدرهای خلخال (F1..F7، استان اردبیل)** است — بنابراین پس از ورود همان شیپ‌فایل‌ها و اجرای توپولوژی، نقشه همان فیدرهای خلخال است؛ با ورود شیپ‌فایل‌های منطقه دیگر، نقشه همان منطقه می‌شود. نقشه پس از اجرای توپولوژی (تب Topology) پر می‌شود، چون ردیابی فیدرها و زون‌بندی ورودی نقشه هستند.
